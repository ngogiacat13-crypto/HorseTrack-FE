Non-Screen Functions

#	Feature	System Function	Description
1	Payment Integration	VNPay IPN Callback API	Receives the server-to-server callback from VNPay. Verifies the secure hash, the transaction reference and the amount against the invoice before changing anything. If valid, sets the payment to VERIFIED and the invoice to PAID, or to REACTIVATION_PENDING if the service was suspended (BR_14). Runs only once per transaction (idempotent). The browser return page never marks an invoice as paid (BR_12).
2	Training Safety	Threshold Check Service	Runs every time a Groom saves a session reading (heart rate, speed). If a value exceeds the session threshold, it changes the session to PAUSED_PENDING_TRAINER, blocks new readings, and sends an urgent alert to the Head Trainer (BR_02). It also refuses to start or resume a session for a horse under a training lock (BR_01).
3	System Security	Audit Logging Service	Automatically writes an Audit_Logs record for every administrative action and important status change: create/update/delete of key data, training lock/unlock, registration approval/rejection, protocol status changes, service suspension/reactivation and role changes. Each record stores who, when, IP, the object, the old → new status and the reason (BR_06, BR_10).
4	Task Monitoring	SLA Monitor (scheduled job)	Runs every few minutes and finds Groom tasks still not done 45 minutes after their start time. Marks them late and notifies the Club Manager (BR_05).
5	Billing	Overdue Invoice Scheduler (daily job)	Recalculates days overdue for unpaid invoices. After the 10-day grace period it applies the configured penalty and notifies the owner (BR_12). It warns the owner before the 25-day mark, and at 25 days flags the invoice for suspension by the Club Manager (BR_13).
6	Inventory	Stock Threshold Alert	After every stock movement (receive, issue, hold, release) it recomputes available = on hand − held. When available stock falls below the safety level, it alerts the Warehouse Manager (BR_08).
7	Inventory	Delayed Shipment Alert	When a purchase order's ETA passes, or is moved later than the date a protocol needs the medicine, it marks the order DELAYED. It also moves the linked protocol to REQUIRES_VET_REVIEW and notifies the Veterinarian (BR_07).
8	Communication	Notification Service	Stores and delivers in-app notifications to the right role. Examples: new vet case, stock answer or ETA, race proposal awaiting the owner, invoice due or overdue, training lock or unlock.
9	System Security	Authentication & Authorization	Hashes passwords, manages login sessions and locks accounts after repeated failed logins. Enforces role-based access on every API call, including data scope: an owner sees only their own horses and a trainer only their assigned horses (BR_09).
